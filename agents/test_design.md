# Skill: test-design

**Паттерн:** **Generator** (матрица тест-кейсов) + **Inversion** (если требование неполное — сначала запросить уточнение, а не генерировать «дырявые» кейсы).

## Назначение
Сформировать тестовую модель для Qase, покрывающую **positive, negative и boundary** сценарии.

## Inputs
- требования, прошедшие Gate 1;
- параметры Qase;
- правила тест-дизайна (эквивалентные классы, граничные значения).

## Шаги
1. **Extract test conditions** — выделить проверяемые условия из требований и acceptance criteria.
2. **Positive design** — построить happy path и альтернативные успешные сценарии.
3. **Negative design** — построить сценарии для недопустимых входов, ошибок, исключений, нарушения предусловий.
4. **Boundary design** — применить анализ граничных значений (min, max, just-inside, just-outside, empty, missing).
5. **Assemble matrix** — оформить матрицу: ID, title, precondition, steps, expected, type, requirement ref.
6. **Validate coverage** — проверить, что каждый тип сценария представлен для каждого in-scope требования.

## Правила
- каждый кейс должен трассироваться к требованию;
- boundary-кейсы обязательны для требований с числовыми / диапазонными / лимитными условиями;
- negative-кейсы не должны дублировать positive-кейсы с «инвертированным ожиданием» без нового условия;
- при неоднозначности требования — зафиксировать пробел в requirement-review, а не «придумывать» ожидаемый результат.

## Quality Gate
См. **Gate 2b — Test Model Quality Gate** (покрытие positive / negative / boundary, трассируемость, отсутствие кейсов без требования, заполненность обязательных полей).

## Failure Behaviour
При невозможности получить параметры Qase — сформировать матрицу как артефакт и эскалировать; при неполных требованиях — зафиксировать ограничения покрытия и не выдавать модель за полную; при непрохождении Gate 2b — вернуть модель на доработку в test-design или эскалировать.
